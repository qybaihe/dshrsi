过程The work itself

一路上碰了多少壁How much got in the way

失败的工具调用不都是一回事。测试没过、编译报错，是活儿本身还没做对。命令不存在、路径不存在、编辑没对上，是环境在挡路，这一种才是 Harness 能学着绕开的。剩下的是分类器叫不出名字的非零退出。两边用同一段代码从会话日志里数。 Not every failed tool call is the same thing. A failed test or a compile error is the work not being right yet. A missing command, a path that is not there or an edit that did not apply is the surroundings getting in the way, and only that kind is something a harness can learn its way around. The rest are non-zero exits the classifier has no name for. Both arms are counted from the session logs by the same code.

跑评测的时候，它在改自己While the benchmark ran, it was changing itself

评测没有给插件任何提示。下面是它在所选模型和轮次里自己写出、通过校验并挂载的适配。“起作用”是它实际拦截、补充或要求验证的次数。 The plugin was given no hints for the benchmarks. These are the adaptations it wrote, validated and mounted by itself for the selected model and pass. “Acted” counts how often one actually refused, annotated or demanded a check.

同一个麻烦反复出现时When the same trouble keeps coming back

差别在这里This is where the difference is

基准里每道题都是一个全新的干净目录，同一个麻烦很少出现第二次。Polyglot 的 Rust 题是个例外：提示词让模型去改 lib.rs，文件其实在 src/lib.rs，于是同一个失败的调用一再出现。一格是一个会话，按开始的先后排列。 In a benchmark every task is a fresh, clean directory, and the same trouble rarely comes twice. The Rust exercises of Polyglot are an exception: the prompt tells the model to edit lib.rs, the file is at src/lib.rs, and so the same failed call keeps coming back. One square is one session, in the order they started.

方法Method

怎么跑的How it was run

两组Two arms原版：@deepseek-ai/dsh 0.2.2-rc.3，headless profile。对照：同一个 Harness 加上默认配置的 dsh-rsi。除此之外没有任何差别。Stock: @deepseek-ai/dsh 0.2.2-rc.3, headless profile. Compared with: the same harness plus dsh-rsi at its default settings. Nothing else differs.
模型Model小米 MiMo 的 mimo-v2.6-flash，两组用同一个模型。Xiaomi MiMo mimo-v2.6-flash; both arms use the same model.
沙箱SandboxDSH 的 workspace-write：只能写这道题的工作目录和一个共享的构建缓存目录，从不向人请求批准。网络没有限制。DSH's workspace-write: writes only inside the task's workspace and one shared build-cache directory, and no approval is ever asked for. The network is not restricted.
适配库Adaptation library一轮里所有会话共用一个 Harness 目录，所以一个会话学到的，后面开始的会话都能用上。同时跑 8 到 12 个会话。每个基准都从空的适配库开始。All sessions of a run share one harness home, so what one session learns is there for every session that starts after it. 8 to 12 sessions run at a time. Every suite starts with an empty library.
Aider Polyglot225 道 Exercism 题，C++、Go、Java、JavaScript、Python、Rust。用 Aider 的提示词；测试没过就在同一个会话里带着测试输出再来一轮，共两次机会。用题目自带的测试判分。225 Exercism exercises in C++, Go, Java, JavaScript, Python and Rust, with Aider's prompts. If the tests fail there is one more turn in the same session with the test output, two tries in all. Scored with the exercise's own tests.
HumanEval+ · MBPP+164 和 378 个 Python 函数。函数桩或描述放在 solution.py 里，用 EvalPlus 0.3.1 判分：原始测试，以及 EvalPlus 扩充后的测试。测试不放进工作目录。164 and 378 Python functions. The stub or the description is placed in solution.py; scored by EvalPlus 0.3.1 on the original tests and on its extended tests. The tests are not in the workspace.
LiveCodeBench v6v6 新增的 175 道 LeetCode 和 AtCoder 题（43 简单，52 中等，80 困难）。题面在 problem.md，用 LiveCodeBench 自己的评分代码在公开和隐藏测试上判分，每个测试限时 6 秒。The 175 LeetCode and AtCoder problems added in v6 (43 easy, 52 medium, 80 hard). The statement is in problem.md; scored by LiveCodeBench's own evaluator on the public and hidden tests, 6 seconds per test.
机器Machine一台 Apple 芯片的 Mac，16 GB 内存，macOS。Go、Rust、CMake、JDK 21、Python 3.12 来自 Homebrew 和 uv。Polyglot 的 225 个参考答案在这套环境下全部通过。One Apple-silicon Mac with 16 GB of memory, macOS. Go, Rust, CMake, JDK 21 and Python 3.12 from Homebrew and uv. All 225 Polyglot reference solutions pass in this environment.
这些数字不能和排行榜比。这里的智能体可以反复读、改、运行代码，一轮最长 30 分钟；排行榜上的同名基准只给模型一次作答机会。这里比的是两套 Harness，不是模型。 These numbers are not comparable with leaderboards. Here the agent can read, edit and run code as often as it wants, for up to 30 minutes a turn; leaderboard runs of the same benchmarks give the model one shot. What is compared here is two harnesses, not models.

没做到的What this does not cover

  • SWE-bench 和 Terminal-Bench 没有跑。它们每道题要一个容器镜像，这台机器的磁盘放不下。这两个基准的任务都在同一个大仓库或同一套环境里反复操作，是最可能体现差别的地方，也是下一步要补的。SWE-bench and Terminal-Bench were not run. They need a container image per task, and this machine does not have the disk for them. Their tasks work repeatedly inside one large repository or one environment, which is where a difference is most likely to show, and they are what comes next.
  • LiveCodeBench 没有跑完，第 2 轮没有跑。模型账户的余额在 LiveCodeBench 中途用尽。第 2 轮是带着第 1 轮留下的适配库把同样的题再跑一遍，最能检验“递归”这两个字，它还欠着。LiveCodeBench is partial, and there is no second pass. The model account ran out of balance part-way through LiveCodeBench. A second pass, the same tasks again on the library the first pass left behind, is the most direct test of the word “recursive”, and it is still owed.
  • 每种配置只跑了一次。同一配置跑两次会差多少还没有量过，配对检验是目前防止把波动当成效果的手段。One run per configuration. How much two runs of the same configuration differ has not been measured; the paired tests are what keeps noise from being read as an effect.
  • 一个模型家族，一台机器。没有在别的模型、Linux 或 Windows 上验证。One model family, one machine. Not verified on other models, on Linux or on Windows.
  • 会话可以联网，沙箱只限制写文件。两组条件相同。Sessions can reach the network; the sandbox confines writes only. The condition is the same for both arms.

自己跑一遍Run it yourself

git clone https://github.com/qybaihe/dshrsi.git && cd dshrsi && npm install
bench/setup.sh                                   # toolchains, datasets, scoring code
node bench/run.mjs polyglot --validate           # reference solutions through the scoring commands

export MIMO_API_KEY=... MIMO_MODEL=mimo-v2.6-flash
node bench/run.mjs polyglot --arm dsh --run flash-dsh-p1 --concurrency 12
node bench/run.mjs polyglot --arm rsi --run flash-rsi-p1 --concurrency 12
node bench/report.mjs --write                    # tables and bench/results/*.json

每道题的结果在仓库的 bench/results/ 里，这一页没有展示的运行也在那里。 Per-task results are in bench/results/ in the repository, including runs this page does not show.
